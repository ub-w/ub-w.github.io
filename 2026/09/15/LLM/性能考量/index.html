性能考量

GPU 性能优化不是套用技巧，而是先定位限制性能的资源，再选择针对性的手段：

一、先判断瓶颈

瓶颈是当前限制 kernel 性能的主要因素。它取决于程序和运行它的 GPU，同一段代码换到不同设备上，瓶颈可能改变。

瓶颈 典型现象 优先检查
内存带宽受限 DRAM 吞吐量接近上限 访存量、数据复用
计算吞吐量受限 某类计算管线接近上限 算法、精度、计算单元
延迟隐藏不足 计算与内存吞吐量都不高，warp 经常等待 occupancy、依赖链
分支或同步受限 分歧、barrier 或 atomic 等待严重 控制流、竞争关系
资源受限 驻留 block 数少 寄存器、共享内存、block 大小

延迟与带宽的区别

  • 延迟：一次操作从发出到完成需要多久；
  • 带宽：单位时间最多可以传输多少数据。

增加活跃 warp 可以隐藏延迟，但不能突破 DRAM 带宽上限。若带宽已经跑满，继续增加线程通常不会让数据传输更快。

二、根据瓶颈选择优化方式

本章的六种方法可以按解决的问题分成三组：

优化目标 看到的问题 优化方式 主要代价
提高执行并行性 没有足够工作覆盖等待 调整资源，提高 occupancy 缓存竞争、资源压力
提高执行并行性 同一 warp 走不同分支 减少控制流分歧 可能需要重排数据或算法
提高内存效率 一个 warp 的地址分散 合并访存 可能需要改变索引或布局
提高内存效率 相同数据被反复读取 共享内存 tiling 占用共享内存、需要同步
减少冗余与竞争 大量线程重复相同工作 线程粗化 增加寄存器、减少并行度
减少冗余与竞争 多个线程争抢同一输出 私有化 增加局部存储和归并步骤

核心主线： 增加可执行工作、减少无效执行、减少无效访存、复用数据、减少重复工作、减少输出竞争。

1.提高 occupancy

核心： 一个 warp 等待时，让 SM 能切换到其他已经就绪的 warp。

一个 warp 通常包含 32 个线程。当 warp 因访存或指令依赖而等待时，warp scheduler 可以调度其他 warp：

Occupancy 是一个 SM 上的活跃 warp 数量与其最大活跃 warp 数量之比，主要受以下因素限制：

  • 每个 block 的线程数；
  • 每个线程使用的寄存器；
  • 每个 block 使用的共享内存；
  • GPU 的 thread、warp 和 block 数量上限。

高 occupancy 不等于高性能。活跃 warp 足以隐藏延迟后，继续增加 occupancy 可能没有收益，还可能增加缓存竞争。因此它是诊断指标，不是必须达到 100% 的目标。

DRAM Bank 与延迟隐藏

多个 DRAM Bank 不是一种独立的代码优化。它是在说明：足够多的独立访存请求，可以利用内存系统内部的并行处理能力，在部分请求等待时推进其他请求。

程序员真正能做的是提供足够的独立工作、减少不必要访存，并让访存模式更规整。

2.减少控制流分歧

核心： 分歧关注的是同一个 warp 内部，而不是不同 warp 之间。

如果同一个 warp 中的线程选择不同分支，硬件需要分别推进不同路径。执行某条路径时，其他路径上的线程不会贡献有效工作。

优化方向包括：

  • 让同一 warp 处理行为相近的数据；
  • 重排数据，减少 warp 内部的分支混合；
  • 在确有收益时，用统一计算替代复杂分支。

目标不是消灭所有 if，而是减少代价高的 warp 内分歧。

5.线程粗化

核心： 用更少的线程重复开销和更高的数据复用，交换一部分并行度与寄存器。

三、优化之间的权衡

想获得的收益 可能付出的代价
更多活跃 warp 隐藏延迟 更大的缓存工作集
更大的 tile 提高复用 更多共享内存、更低 occupancy
更高粗化因子减少重复工作 更多寄存器、更少并行任务
私有化减少原子竞争 更多局部存储和归并工作

不存在脱离具体 kernel 和设备的“最佳 block 大小”“最佳 tile 大小”或“最佳粗化因子”。最终判断标准是正确性和实际运行时间。

四、实际优化流程

  1. 先使用 CUDA Event 找到耗时 kernel；
  2. 使用 Nsight Compute 判断计算、内存还是延迟受限；
  3. 检查 warp 分歧、访存模式和重复数据传输；
  4. 检查 occupancy 被寄存器还是共享内存限制；
  5. 每次只改变一个主要因素，保存优化前后的基线；
  6. 优化后重新判断瓶颈，因为瓶颈可能已经转移。

五、总结

  • 性能优化的第一步是定位瓶颈，而不是直接套用某种优化方法。
  • Occupancy 和控制流分歧主要影响 GPU 能否持续执行有效指令。
  • 合并访存减少一次 warp 访存产生的事务；tiling 通过数据复用减少全局内存访问次数。
  • 线程粗化减少重复工作，私有化减少公共输出竞争，但都会消耗更多线程私有资源。
  • 优化是在并行度、寄存器、共享内存、缓存和访存流量之间进行交换。
  • 最终流程始终是：测量 → 判断瓶颈 → 修改 → 再次测量。
