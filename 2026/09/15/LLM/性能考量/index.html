性能考量

GPU 性能优化的目标，不是让某个指标看起来更高，而是让硬件用更少的时间完成同样的有效工作。

学习这一部分时，可以始终追问三个问题：

  1. 计算单元为什么没有持续工作？
  2. 内存系统搬运的数据是否都被有效使用？
  3. 为解决一个问题付出的资源代价，是否制造了新的瓶颈？

本文以 CUDA 矩阵乘法为主线，把 occupancy、控制流分歧、合并访存、共享内存分块和线程粗化联系起来。

一、先判断瓶颈，再选择优化

瓶颈是当前限制 kernel 性能的主要因素。它既取决于程序，也取决于运行它的 GPU；同一个 kernel 换到另一代 GPU 上，瓶颈可能发生变化。

常见瓶颈可以粗略分为以下几类：

瓶颈 典型现象 优先考虑
内存带宽受限 DRAM 吞吐量接近上限，计算管线没有跑满 减少内存流量、提高数据复用
计算吞吐量受限 某类计算管线接近峰值 减少计算、使用更合适的数据类型或计算单元
延迟隐藏不足 计算和内存吞吐量都不高，但 warp 经常等待 增加独立工作、检查 occupancy 和依赖链
分支或同步受限 warp 分歧严重，或频繁等待 barrier/atomic 重组控制流、减少同步和竞争
资源受限 寄存器或共享内存限制驻留 block 数量 调整 block、tile 和粗化因子

1. 带宽和延迟不是同一个问题

  • 延迟：一次操作从发出到完成要等多久；
  • 带宽：单位时间内最多能搬运多少数据。

增加活跃 warp 主要是在隐藏延迟，不能突破 DRAM 的带宽上限。如果内存带宽已经跑满，再增加线程通常不会使数据传输更快。

2. 正确的优化流程

优化后的代码必须同时满足两项要求：结果正确，并且端到端运行时间确实下降。

二、GPU 怎样隐藏延迟

1. Warp 调度

NVIDIA GPU 以 warp 为基本调度单位，一个 warp 通常包含 32 个线程。当某个 warp 因全局内存访问或指令依赖而暂时不能继续时，warp scheduler 可以选择另一个已经就绪的 warp 执行。

延迟并没有消失，只是等待时间被其他有用工作覆盖了。

2. Occupancy 是什么

Occupancy 是一个 SM 上的活跃 warp 数量与该 SM 所支持的最大活跃 warp 数量之比。

它主要受以下资源限制：

  • 每个 block 的线程数；
  • 每个线程使用的寄存器数量；
  • 每个 block 使用的共享内存；
  • 硬件允许的最大 thread、warp 和 block 数量。

低 occupancy 往往会削弱隐藏延迟的能力；但高 occupancy 不等于高性能。只要已经有足够的可执行 warp，继续增加 occupancy 可能没有收益，还可能增加缓存竞争。

因此，occupancy 应被看作“是否有足够并发工作”的诊断指标，而不是必须追求 100% 的目标。

3. 多个 DRAM Bank 应该怎样理解

课件中的“多个 DRAM Bank 隐藏延迟”是在解释内存系统为什么需要大量并发请求，而不是一种独立的代码优化方法。

现代 GPU 的内存层次包含 cache、memory partition、controller 和 DRAM bank 等多个层次。足够多的独立访存请求可以利用这些硬件的并行处理能力。当一部分请求还在等待时，内存系统可以推进其他请求。

程序员真正能够做的是：

  • 提供足够的独立工作和活跃 warp；
  • 减少不必要的访存；
  • 让访存模式更规整；
  • 避免过长的数据依赖链。

所以 DRAM Bank 属于“occupancy 为什么有助于隐藏访存延迟”的硬件背景，不需要把它当作与 tiling 并列的优化技巧。

三、减少无效执行：控制流分歧

同一个 warp 中的线程共享指令执行过程。如果它们在数据相关的分支中选择不同路径，硬件需要分别推进这些路径；执行某条路径时，不属于该路径的线程不会贡献有效工作。

优化目标不是消灭所有 if，而是尽量让同一个 warp 中的线程做相同选择。例如，可以调整数据排列，让相似任务由同一 warp 处理。

判断分歧时要以 warp 为范围。不同 warp 走不同路径通常不是这里所说的 warp 内控制流分歧。

四、降低全局内存代价

全局内存优化有两个不同层次：

  1. 合并访存：一次 warp 访存怎样用尽可能少的事务完成；
  2. 数据复用：怎样从根本上减少需要进行的全局内存访问。

合并访存解决“每次访问是否浪费”，tiling 解决“是否访问了太多次”。二者不能互相替代。

1. 合并访存

当一个 warp 执行一条全局内存指令时，32 个线程会产生一组地址。硬件会用覆盖这些地址所需的内存事务来完成访问。优化目标是让这些地址集中在尽可能少的内存段中，提高“实际使用字节数 / 搬运字节数”。

  • B[i * N + col]：线程读取同一行的连续元素，属于典型的合并访问；
  • C[row * N + col]：线程写入连续元素，也可以合并。

五、线程粒度与线程粗化

线程粒度表示每个线程承担多少输出工作。

1. 细粒度线程

常见的初始设计是让每个线程处理最小输出单元：

  • 向量加法：一个线程计算一个元素；
  • 图像处理：一个线程计算一个像素；
  • 矩阵乘法：一个线程计算一个 C 元素。

它的优点是并行任务充足、线程映射直观，并且程序可以自动利用拥有更多 SM 的 GPU。缺点是大量线程可能重复执行索引计算、加载相同数据或参与同步。

4. 粗化的收益与代价

收益：

  • 一个 A tile 被多个输出 tile 复用；
  • 减少重复的全局内存读取；
  • 减少部分索引、控制和 block 级开销。

代价：

  • sum[4] 增加每个线程的寄存器需求；
  • 单个 block 工作时间更长；
  • block 总数减少，可用并行性下降；
  • 更多寄存器可能降低 occupancy。

也可以一次把四个 B tile 全部放入更大的共享内存，从而减少 barrier 次数，但会增加共享内存占用。这两种实现没有绝对优劣，需要测量。

七、优化之间为什么会冲突

1. Occupancy 与缓存局部性

更多活跃 warp 有利于隐藏延迟，但过大的并发工作集可能造成缓存竞争。达到足够的延迟隐藏能力后，更高 occupancy 不一定继续提升性能。

2. Tiling 与 occupancy

更大的 tile 可能带来更多复用，但每个 block 使用的共享内存也更多，一个 SM 能同时驻留的 block 数量可能下降。

3. 粗化与 occupancy

更高的粗化因子减少重复工作，却增加每线程寄存器需求并减少线程数量，可能削弱延迟隐藏能力。

因此不存在脱离具体 kernel 和设备的“最佳 block 大小”“最佳 tile 大小”或“最佳粗化因子”。正确做法是选择若干合理候选值，结合 profiler 和运行时间进行比较。

八、实践检查清单

1. 正确性

  • 是否覆盖矩阵或张量边界？
  • barrier 是否会被 block 中所有线程以一致方式执行？
  • 优化前后的结果误差是否在允许范围内？

2. 执行效率

  • 是否存在严重的 warp 内分支分歧？
  • 是否有足够的 eligible warp 隐藏延迟？
  • occupancy 被寄存器、共享内存还是 block 大小限制？

3. 内存效率

  • 对每条访存指令，同一 warp 的地址落入多少个 segment？
  • 是否存在大步长访问或大量无效字节传输？
  • 相同数据是否被反复从全局内存读取？
  • 共享内存是否存在 bank conflict？

4. 性能验证

  • 使用 CUDA Event 测量 kernel 时间，并进行预热和多次重复；
  • 使用 Nsight Compute 的 Speed of Light、Memory Workload Analysis、Occupancy 和 Source Counters 等部分定位问题；
  • 使用 Roofline 判断当前更接近带宽受限还是计算受限；
  • 每次只改变一个主要因素，并保存优化前后的基线。

九、把所有优化放回一条主线

最终原则是：先测量，再解释；先定位瓶颈，再选择优化；每次优化后重新测量。
